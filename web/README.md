# Ghani Group Rental — v1.0

منصة تأجير معدات التصوير السينمائي لشركة Ghani Group: موقع ويب + REST API (جاهز لتطبيق الموبايل) + لوحة تحكم + معالج تنصيب يرحّل الكتالوج كاملاً إلى قاعدة البيانات.

## التنصيب (5 دقائق)

1. ارفع محتويات المجلد إلى السيرفر (مثلاً `public_html/` أو `public_html/rental/`).
2. أنشئ قاعدة بيانات MySQL / MariaDB ومستخدماً لها (أو دع المعالج ينشئها إذا كانت صلاحيات المستخدم تسمح).
3. اعطِ صلاحية الكتابة: `chmod -R 775 config storage uploads`
4. افتح `https://your-domain.com/install/` واتبع الخطوات:
   - فحص المتطلبات ← بيانات القاعدة (+ سيرفرات القراءة اختياري) ← بيانات الموقع والمدير ← **تنصيب**
   - المعالج ينشئ 13 جدول، ويرحّل 72 معدة و 8 أقسام و 4 باقات مع كل الصور، وينشئ حساب المدير، ويكتب `config/config.php`، ثم يقفل نفسه.
5. **احذف مجلد `install/`** بعد الانتهاء.
6. لوحة التحكم: `https://your-domain.com/admin`

### المتطلبات
- PHP 8.1+ مع: `pdo_mysql`, `gd`, `mbstring`, `json` (+ `curl` لاستيراد صور من روابط)
- MySQL 5.7+ أو MariaDB 10.3+
- Apache مع `mod_rewrite` (ملف `.htaccess` جاهز) أو Nginx (انظر `nginx.conf.example`)
- مستحسن: OPcache، و APCu أو Redis للكاش

## هيكل المشروع

```
index.php            نقطة الدخول: /api/v1/* ← API، /admin ← لوحة التحكم، والباقي ← الموقع
app/                 الكود (محمي من الوصول المباشر)
  DB.php             طبقة القاعدة + توزيع القراءة على سيرفرات متعددة
  Cache.php          كاش Redis / APCu / ملفات
  Security.php Auth.php Validator.php Upload.php
  Importer.php       ترحيل/استيراد البيانات والصور
  Controllers/       Public, Auth, Order, Admin
  routes.php         كل مسارات الـ API
assets/              الموقع ولوحة التحكم (HTML/CSS/JS بدون أي مكتبات خارجية)
install/             معالج التنصيب + schema.sql + seed/ (بيانات الكتالوج وصوره)
config/              config.php (يُنشأ عند التنصيب)
storage/             الكاش والسجلات
uploads/equipment/   صور المعدات (تنفيذ PHP ممنوع داخله)
docs/API.md          توثيق الـ API الكامل
```

## توزيع الأحمال

| الطبقة | ما تم تطبيقه |
|---|---|
| **قاعدة البيانات** | فصل القراءة عن الكتابة: الكتابة على الرئيسي، القراءة موزعة عشوائياً على سيرفرات القراءة (Read Replicas). سيرفر القراءة المتوقف يُستبعد 30 ثانية تلقائياً ويُستخدم الرئيسي مكانه. بعد أي كتابة يقرأ نفس العميل من الرئيسي لمدة 5 ثوانٍ (sticky) حتى لا يرى بيانات قديمة. التحقق من المخزون عند تأكيد الحجز يتم دائماً على الرئيسي داخل معاملة مع `FOR UPDATE`. |
| **الكاش** | كل واجهات الكتالوج مُكاشة مع "إصدارات": أي تعديل من لوحة التحكم يُبطل كاش الكتالوج كاملاً بخطوة واحدة. Redis يُستخدم تلقائياً إذا تم إدخاله (مشترك بين عدة سيرفرات ويب)، وإلا APCu، وإلا ملفات. |
| **HTTP** | `ETag` + `Cache-Control` + `stale-while-revalidate` على الواجهات العامة، فيمكن وضع Cloudflare أو أي CDN أمام الموقع مباشرة. ردود `304` بدون جسم. |
| **الويب** | التطبيق stateless (الجلسات في القاعدة وليس في ملفات PHP)، فيمكن تشغيل عدة سيرفرات ويب خلف موزّع أحمال. `/api/v1/health` جاهز لفحص صحة السيرفرات. مثال upstream في `nginx.conf.example`. |
| **القاعدة** | فهارس على كل أعمدة البحث والفلترة، وتقسيم الصفحات بحد أقصى 60، وتحديث "آخر استخدام" للجلسات مرة كل 5 دقائق فقط لتقليل الكتابة. |

لإضافة سيرفرات قراءة لاحقاً، عدّل `config/config.php`:
```php
'replicas' => [
    ['host' => '10.0.0.12', 'port' => 3306],
    ['host' => '10.0.0.13', 'port' => 3306, 'user' => 'reader', 'pass' => '...'],
],
```
وإذا كان الموقع خلف موزّع أحمال أو Cloudflare، أضف عناوينه في `security.trusted_proxies` ليُقرأ IP الزائر الحقيقي.

## الحماية

- **SQL Injection**: كل الاستعلامات prepared statements، وأسماء الأعمدة والترتيب من قوائم ثابتة فقط.
- **XSS**: الواجهات تهرّب كل نص قبل عرضه، و Content-Security-Policy يمنع أي سكربت خارجي أو inline في الموقع ولوحة التحكم.
- **CSRF**: كوكي `SameSite=Strict` + توكن double-submit لكل طلب كتابة من المتصفح.
- **الجلسات**: توكن عشوائي 256-bit، يُخزَّن في القاعدة كـ HMAC-SHA256 فقط. الكوكي `HttpOnly` و `Secure` على HTTPS.
- **كلمات المرور**: Argon2id (أو bcrypt cost 12)، قفل الحساب 15 دقيقة بعد 5 محاولات، ورسالة موحدة لا تكشف إن كان البريد مسجلاً.
- **Rate limiting**: على كل الـ API، وأشد على الدخول والتسجيل وإنشاء الطلبات.
- **رفع الملفات**: فحص النوع الحقيقي، إعادة ترميز كل صورة عبر GD (يزيل أي كود مخفي و EXIF)، أسماء عشوائية، ومنع تنفيذ PHP في مجلد الرفع.
- **الاستيراد من روابط**: حماية SSRF — لا يُسمح بالتنزيل من عناوين داخلية.
- **الصلاحيات**: عميل / موظف / مدير. الحذف وإدارة المستخدمين والإعدادات للمدير فقط. كل عمليات لوحة التحكم مسجّلة في سجل العمليات.
- **الملفات الحساسة**: `app/ config/ storage/ install/seed` محمية، وملف الإعدادات بصلاحية 640.
- ترويسات: HSTS، X-Frame-Options، nosniff، Referrer-Policy، Permissions-Policy.
- البوتات: حقل honeypot مخفي في نموذج الطلب.

## استيراد بيانات إضافية

لوحة التحكم ← **استيراد وتصدير**: ارفع JSON أو CSV (يوجد نموذج CSV للتنزيل). حقل `image` يقبل رابطاً مباشراً لصورة، يُنزَّل ويُحسَّن تلقائياً. الاستيراد يحدّث المعدات الموجودة بنفس الـ slug ولا يكررها.

## صفحات المتاجر (v1.1)

صفحات عامة يطلبها App Store و Google Play، تقرأ بيانات الشركة من الإعدادات تلقائياً:
`/privacy` سياسة الخصوصية · `/terms` الشروط · `/support` الدعم · `/delete-account` حذف الحساب.
ومن لوحة التحكم ▸ الإعدادات: أقل إصدار مسموح للتطبيق (إجبار التحديث)، روابط المتجرين، ورسالة صيانة تظهر في التطبيق فوراً.

## تطبيق الموبايل

كل ما يحتاجه التطبيق موجود في الـ API (`docs/API.md`). استخدم `Authorization: Bearer` بدل الكوكي، وأضف دومين التطبيق في `security.cors_origins` إن كان تطبيق ويب.

## نقل الموقع لسيرفر آخر

انسخ الملفات + `uploads/` + تصدير القاعدة (`mysqldump`)، وعدّل بيانات القاعدة و `app.url` في `config/config.php`.
